# Data dictionary

The default dataset is generated by `claimshield.synthetic_data` and is entirely synthetic. IDs and records do not represent real members, clinicians, facilities, or claims.

| Field | Type | Description |
|---|---|---|
| `claim_id` | string | Synthetic claim identifier; duplicate IDs are intentionally injected in the demo dataset to exercise validation. |
| `member_id` | string | Synthetic member identifier. |
| `provider_id` | string / nullable | Synthetic provider identifier; some missing values are injected to exercise quality checks. |
| `service_date` | date | Fictional date of service. |
| `submission_date` | date | Fictional submission date, normally on or after service date. |
| `procedure_code` | string | Fictional selection from a small set of example procedure codes. |
| `diagnosis_group` | category | Broad synthetic category, not a clinical diagnosis. |
| `place_of_service` | category | Synthetic service setting. |
| `claim_amount` | decimal-like number | Synthetic submitted amount, in unspecified demo currency units. |
| `paid_amount` | decimal-like number | Synthetic paid amount. |
| `claim_status` | category | One of paid, denied, pending, adjusted. |
| `reviewed_by_human` | boolean | Synthetic review indicator; not used as a ground-truth fraud label. |
| `source_is_synthetic` | boolean | Identifies the default generated data as synthetic. |

## Data handling rules

- Never commit real patient or member data, credentials, or unauthorized datasets.
- If using an external dataset, document its source, license, permitted use, and transformations before use.
- Do not interpret anomaly flags as proof of fraud or misconduct.
